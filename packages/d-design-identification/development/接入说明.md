# 网站与GitHub接入

本轮仅整编本地规则包。旧包的独立极端加载路径已改为统一目录；没有执行上传、安装、网站同步或部署。

## 数据与代码入口

将完整文件夹放到仓库 `packages/d-design-identification/`。数据入口为根目录 `manifest.json`，包版本1.1.0、数据适配API版本2。规则模块为常规0.5.0、极端1.0.1、共用组件1.0.0；这些版本变化代表重组，不表示候选数值已获品牌批准。

```text
rules/common.json                 通用组件唯一维护位置
rules/regular.json                常规差异
rules/extreme.json                极端差异
references/asset-bindings.json     资产元数据唯一维护位置
```

不能只替换旧网站的 `public/configs/ginkgo-split.json`。新JSON通过引用共用参数，布局器需调用 `runtime/components.mjs`的兼容视图函数。不要再保留一份人工更新的组件快照。

## 本地服务

```javascript
import {loadBundle} from './runtime/load-rules.mjs';
import {resolveConstraints} from './runtime/extreme.mjs';
const bundle = await loadBundle();
// bundle.regular 是已合并共用参数的常规规则；bundle.rules/common 适配极端旧接口。
const plan = resolveConstraints(request, bundle.rules, bundle.common);
```

两个适配器从同一份JSON生成数据视图，保留极端文本宽度1600、行数2等显式覆盖。常规M使用1200，S/L/XL没有借此完成其全部文字模板。共用边距与字号基准改变会同步进入两个视图，不会改掉各模块字数和QR差异。

## 可选GitHub数据加载

`integration/github-loader.mjs`只下载固定40位提交下的统一清单、四个数据JSON和Skill文本，并核对摘要及组件依赖；不下载执行JavaScript。运行代码须先随应用部署。私有仓库认证由团队后台已有机制处理，不将凭据放进包里。

```javascript
import {loadGithubBundle} from './development/integration/github-loader.mjs';
import {resolveProjectMaterial} from './development/integration/project-adapter.mjs';
const bundle = await loadGithubBundle(approvedCommit);
const result = resolveProjectMaterial(project, material, bundle);
```

测试使用模拟fetch，检查通过不代表已连接真实GitHub。旧项目二维码URL只作元数据，极端适配器不将它传给绘制函数。

## 后续平台工作

按每个物料分别分流：常规走已合并的常规规则；固定6:1／1:6走极端模块；其他不支持的极端比例提示未支持。布局器仍需加载真实资产/字体、应用断行、检查每张图及制作可交付文件。修改内容后让旧预览失效，审核绑定生成快照。

AI语义断行目前只有规则，网站需要单独实现并给用户提供调整入口。`auditRenderedLayout`检查可信布局器提交的结构化数据，不直接看截图、不调用模型，不替代真实字体和品牌验收。

若启用CI，将 `development/github/check-rules.yml`复制到实际仓库 `.github/workflows/`，保留已有工作流。源码字段、规则来源和历史项目快照也需接入新清单；本包不会自动迁移它们。
